# Как устроен фикс

[English](implementation.md) | **Русский**

Фикс состоит из прокси `xinput1_3.dll`, который кладётся рядом с `SplitSecond.exe`, правок двух
роликов интерфейса в `data/resident.ark` и установщика, который всё это ставит и снимает.

Поддерживаются три сборки `SplitSecond.exe`, все под защитой SecuROM:

| Сборка | `TimeDateStamp` | `SizeOfImage` | Заголовок PE |
|---|---|---|---|
| коробочная (retail) | `0x4BE3EA74` | `0x1A64000` | `0xD40` |
| Steam, английская (с дополнительной секцией Steam DRM `.bind`) | `0x4BE13C66` | `0x1DB7000` | `0xD20` |
| Steam, русская (exe коробочной версии в обёртке Steam DRM) | `0x4BE3EA74` | `0x1DBF000` | `0xD20` |

Код в них одинаковый, только сдвинут: в английской Steam-сборке `.data` на `0x1000` ниже, а
функции — на несколько сотен байт; русская Steam-сборка использует адреса коробочной. В Steam exe
и `data/resident.ark` приходят с языковым пакетом, поэтому смена языка их заменяет. Адреса ниже — для коробочной сборки, адреса Steam-сборки лежат в таблице
`builds` в `src/xinput_fix.c`. Они найдены скриптом `tools/port_addrs.py` по дампам памяти обеих
сборок (см. [инструменты](tooling.ru.md)). С любым другим exe прокси ничего не меняет и только
пересылает вызовы XInput. Оба ролика интерфейса во всех сборках совпадают байт в байт.

## Прокси XInput (`src/xinput_fix.c`)

Игра импортирует из `xinput1_3.dll` только `XInputSetState` (вибрация), сам геймпад она читает
через DirectInput (устройство «Joy 0»). Прокси экспортирует те же функции с теми же ординалами
(`src/xinput1_3.def`), пересылает их в системный XInput (`xinput1_3`, при его отсутствии —
`xinput1_4` или `xinput9_1_0`) и запускает поток, который делает остальное.

### Навигация по меню

Поток опрашивает геймпад 100 раз в секунду. Когда игра в меню (главное меню, пауза, экран
результатов), нажатия превращаются в клавиши через `SendInput`:

| Геймпад | В меню | В гонке |
|---|---|---|
| D-pad / левый стик | стрелки (с автоповтором) | — |
| A / B | Enter / Esc | — |
| X / Y | Space / Tab | — |
| Start | Esc | Esc (пауза) |

Кнопка, зажатая в момент смены «меню ↔ гонка», срабатывает только после отпускания. В гонке
прокси не вмешивается: стики, курки и кнопки идут в игру через DirectInput по её настройкам.
Пауза в игре ставится только клавишей Esc, поэтому Start → Esc работает всегда.

### Геймпады Xbox 360

Игра различает устройства DirectInput по `guidProduct` (функция `0x40DB10`): геймпад Xbox 360
(`045E:028E`) и беспроводной ресивер (`045E:02A1`) получают тип 0, несколько устройств Logitech,
Saitek и других — свои типы. С геймпадом Xbox 360 игра сама управляет меню, и эмуляция клавиш
засчитывала бы каждое нажатие дважды. Поэтому прокси раз в 3 с перебирает игровые устройства
DirectInput и отключает эмуляцию клавиш, пока такой геймпад подключён.

На Steam Deck именно это делает Proton Experimental для Steam-версии (приложение 297860): он
выставляет `PROTON_SPOOF_STEAMINPUT_VIDPID=1`, и виртуальный геймпад Steam Input получает
идентификаторы Xbox 360.

### Запасной путь через DirectInput

В Proton 11.0 Steam-версия вообще не видит геймпад через XInput (все слоты отвечают
`ERROR_DEVICE_NOT_CONNECTED`), а DirectInput — и сама игра в гонке — его видит. Если слот 0 XInput
пуст, прокси читает первый игровой контроллер DirectInput по раскладке, которую игра ждёт от
геймпада Xbox: кнопки 0–7 — это A, B, X, Y, LB, RB, Back, Start, POV-переключатель — крестовина,
оси X/Y — левый стик. Используется свой маленький формат данных (стик, крестовина, 8 кнопок)
вместо `c_dfDIJoystick`, который потянул бы за собой `dxguid`. Устройства перебираются заново раз
в 3 с вместе с проверкой на Xbox 360.

### Как отличить меню от гонки

Меню от гонки отличается по двум глобальным переменным из `.data` exe, найденным сравнением
снимков памяти в разных состояниях игры:

- `[0xD4456C] == 0` — не в гонке (фронтенд);
- `[0xD8C104] != 0` — гонка на паузе или показаны результаты.

### Иконки в подсказках гонки

Тексты подсказок хранятся с метками: `ДЛЯ УСКОРЕНИЯ НАЖМИТЕ *ACTION_THROTTLE*`. Функция
`0x562350` (`cdecl (const char *action, String *out)`) разворачивает метку в название клавиши или
оси — для того устройства, которое игра считает активным в данный момент (`[[0xD65E08] + 0x6C]`).
Если она вернёт `UNKNOWN`, метка остаётся в тексте как есть; такие метки (`*BTN_RT*`, `*BLUE_PP*`
и т. п.) HUD-ролик `Hud.gfx` заменяет картинками через `setImageSubstitutions`.

Прокси ставит на функцию хук (переход на свою функцию, первые 7 байт переносятся в трамплин).
Для действий из списка он берёт привязку из профиля джойстика и возвращает метку картинки:

| Привязка | Метка |
|---|---|
| ось Z− / Z+ (курки) | `*BTN_RT*` / `*BTN_LT*` |
| оси X/Y (левый стик) | `*BTN_LS*` |
| кнопки 0 / 1 / 8 | `*BTN_A*` / `*BTN_B*` / `*BTN_L3*` |
| X, Y, LB, RB, Back, Start, правый стик | короткая подпись (`X`, `Y`, `LB`, …) |

Если действие на геймпад не назначено, работает оригинальная функция.

Профили управления: `[0xD656C8]` → объект, `+0xCF6C` — число профилей, `+0xCF70` — массив по
`0x584` байт. В профиле `+0x564` — тип устройства (1 — клавиатура), `+0x568` — номер. Привязки —
записи по 20 байт начиная со слота `0x1C`: `{ id действия, клавиша (VK), код джойстика, вид, 0 }`,
где вид 0 — кнопка, 1 — ось, 3 — не назначено. Слоты: газ `0x1C`, тормоз `0x1D`, руль
`0x1E`/`0x1F`, камера `0x24`, обзор `0x2A–0x2D`, PowerPlay `0x33`/`0x34`.

Код игры зашифрован SecuROM и расшифровывается в памяти при запуске, поэтому хук ставится, как
только байты функции совпадут с ожидаемыми (пролог и `mov edi, "ACTION_THROTTLE"` на `+0x8C`).

### Сброс управления

Подсказки и навигация рассчитаны на раскладку, в которой геймпад назначен как Joy 0 (RT — газ,
LT — тормоз, левый стик — руль, A/B — PowerPlay, Y — камера, правый стик — обзор), а клавиатура —
на стрелках. По умолчанию в игре геймпад не назначен, поэтому установщик кладёт рядом с exe метку
`ssfix_reset_controls`. Пока она есть, прокси раз в секунду выставляет эту раскладку в профилях 0
(джойстик) и 1 (клавиатура) — только если структура профилей такая, как ожидается.

Сохранение игры (`Documents\Disney Interactive Studios\Split Second\*.sav`) зашифровано, поэтому
записывает его сама игра. Как только файл сохранения обновится после сброса, метка удаляется, и
дальнейшие изменения в настройках управления сохраняются как обычно.

### Лог

`%USERPROFILE%\Documents\ss_xinput_fix.log` (в Proton — внутри префикса,
`.../pfx/drive_c/users/steamuser/Documents/`): версия exe, используемый XInput, переключения
«меню/гонка», установка хука, сброс управления.

## Правки интерфейса в `data/resident.ark`

Интерфейс игры — ролики Scaleform (`.gfx`, SWF с сигнатурой `GFX`) внутри архива
`resident.ark`. Правятся два ролика.

### `UI/CommonUI/Prompt_Bar.gfx` (запись `266e5f18`)

Нижняя строка подсказок. Иконка каждой кнопки (`buttonA_mc` … `buttonSTART_mc`) — клип с кадрами
`Xenon_*`, `PS3_*` и `PC_KeyBlank` / `PC_GenKey` / `PC_GenKeyLong`. PC-версия переключает иконки на
клавиатурные кадры и вписывает в них название клавиши.

`tools/padicons.py` даёт каждой кнопке свой клип иконки, в котором сохранены все метки кадров,
но на любом кадре показана её кнопка Xbox. Какой бы кадр ни выбрала игра, видна кнопка геймпада,
без задержки и мигания. Сама кнопка лежит во вложенном клипе `glyph_mc`, чтобы скрипт
`ui/padicon_frame1.as` мог исправлять её пропорции (см. ниже).

### `UI/Frontend/Flash/FE_pressStart_Overlay.gfx` (запись `51bf9dda`)

Заставка «НАЖМИТЕ ENTER, ЧТОБЫ НАЧАТЬ». Текст — ключ локализации `TEXT_PRESS_START`, который
переводится уже после первого кадра. `tools/pressstart.py` добавляет в ролик клип с кнопкой A
(та же фигура и атлас, что в `Prompt_Bar`) и даёт текстовому полю имя `press_txt`. Скрипт
`ui/pressstart_text.as` ждёт перевода, заменяет слово `ENTER` пробелами под ширину иконки и ставит
иконку на их место. Ищется только `ENTER`: если в переводе его нет, текст остаётся как есть.

### Особенности движка

- Игра рисует только картинки из своих наборов текстур (`*.textures`, сигнатура `SXET`), через
  собственный `cGfxTextureManager::cImageCreator`. Встроенные в ролик bitmap'ы и `BitmapData`
  не отображаются, ссылки на отсутствующие в наборах картинки (их немало осталось от консольной
  версии) — тоже. Поэтому иконки — это фигуры с заливкой из атласа `circle_buttons` набора
  CommonUI, который загружен всегда.
- `setImageSubstitutions` не применяется к уже показанному тексту.
- `getExactCharBoundaries` возвращает границы закрашенной части глифа (у пробела — пустые) и не
  учитывает выравнивание строки; положение иконки считается по соседним символам с поправкой на
  центрирование.
- Интерфейс рисуется в режиме `exactFit`: сцена 1280×720 растягивается на весь экран. На экранах
  не 16:9 (Steam Deck — 16:10) круглые иконки сплющиваются; скрипты растягивают их по горизонтали
  на `(высота экрана / 720) / (ширина экрана / 1280)` по `System.capabilities.screenResolutionX/Y`.

## Установщик (`installer/ssfix_install.c`)

1. Проверяет сборку `SplitSecond.exe` по заголовку PE (`TimeDateStamp` и `SizeOfImage`).
2. Для каждой правки (`patch/*.ssdf`) находит запись в `data/resident.ark` по хэшу имени,
   распаковывает её и сверяет размер и CRC32 с теми, от которых сделан дифф. Если архив уже
   изменён или это другая версия игры — отказывается и ничего не меняет.
3. Сохраняет исходные 20-байтные записи таблицы и размер архива в `data/resident.ark.ssfix`.
4. Применяет диффы, дописывает результат в конец архива (с выравниванием `0x800`) и
   перенаправляет на него записи таблицы (`flag = 0`, без сжатия). Остальной архив не трогается.
5. Записывает `xinput1_3.dll` и метку сброса управления. Чужая DLL с тем же именем сохраняется
   как `.bak`; свою (любой версии) установщик узнаёт по строке `SSFIX-XINPUT-PROXY` внутри.
6. Копирует себя в `ssfix/` и кладёт рядом с exe скрипт удаления.

Повторный запуск сначала откатывает предыдущую установку, так что архив не растёт. Удаление
возвращает записи таблицы, обрезает архив до исходного размера (архив совпадает с оригиналом
байт в байт), удаляет DLL (возвращая `.bak`), метку, скрипт и `ssfix/`.
